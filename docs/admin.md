# Admin & Client Management

`tiredvpn admin` manages clients when the server runs in multi-client mode
(with Redis). Everything it does goes through the management REST API, except
`admin qr`, which is entirely local.

## Prerequisites

The server must be started with `-redis`. The API, the metrics endpoint and the
per-client registry only exist in that mode.

```bash
tiredvpn server \
  -listen :443 \
  -cert server.crt \
  -key server.key \
  -redis localhost:6379 \
  -api-addr 127.0.0.1:8080 \
  -api-token "$(openssl rand -hex 32)"
```

`-api-token` (or `TIREDVPN_API_TOKEN`) is optional. Without it every endpoint is
unauthenticated; the server logs a warning at startup if it is also bound to a
non-loopback address.

## Commands

```
tiredvpn admin add     Add a new client
tiredvpn admin list    List clients
tiredvpn admin delete  Delete a client
tiredvpn admin qr      Print a connection string and QR code
```

### Add a client

```bash
tiredvpn admin add \
  -api http://127.0.0.1:8080 \
  -server vpn.example.com:443 \
  -name alice
```

| Flag | Default | Description |
|------|---------|-------------|
| `-api` | | **required** Management API endpoint, e.g. `http://127.0.0.1:8080` |
| `-server` | | **required** Server address written into the connection string |
| `-name` | | **required** Client name |
| `-api-token` | | Bearer token, when the API requires one. Falls back to `TIREDVPN_API_TOKEN` |
| `-tun-ip` | server-assigned | Fixed tunnel IP. Sent only when non-empty |
| `-max-conns` | `0` | Max concurrent connections. Sent only when `> 0`; `0` means unlimited |
| `-expires-in` | never | Expiry as a Go duration, e.g. `720h`. Sent only when non-empty |
| `-quic` | `true` | `quic` parameter in the connection string |
| `-quic-port` | `8443` | `quicPort` parameter |
| `-strategy` | `auto` | `strategy` parameter |
| `-cover` | `api.googleapis.com` | `cover` parameter |

The ID and secret are generated by the server, not by the CLI. On success the
command prints the ID, the secret, the `tired://` connection string and a QR
code rendered with Unicode block characters:

```
╔════════════════════════════════════════════════════════════════╗
║                    CLIENT ADDED SUCCESSFULLY                   ║
╠════════════════════════════════════════════════════════════════╣
║  Client ID:  7f4e3a21-b8c2-4d19-a5f1-0e8c3d7b1920              ║
║  Secret:     a3f1c9e2...                                       ║
╠════════════════════════════════════════════════════════════════╣
║  Connection String:                                            ║
╚════════════════════════════════════════════════════════════════╝

tired://vpn.example.com:443?cover=api.googleapis.com&fallback=true&quic=true&...
```

Any non-`200`/`201` response prints the status line plus the response body and
exits with status 1.

### List clients

```bash
tiredvpn admin list -api http://127.0.0.1:8080 [-api-token <token>]
```

Prints one line per client: ID, then the name when it has one. The command
reads only `id` and `name` from the response; the other fields the API returns
are ignored.

Only clients the server considers usable appear here - see
[Visibility](#visibility) below.

### Delete a client

```bash
tiredvpn admin delete \
  -api http://127.0.0.1:8080 \
  -id 7f4e3a21-b8c2-4d19-a5f1-0e8c3d7b1920 \
  [-api-token <token>]
```

Deleting removes the client record, the secret index and the stored stats. The
resulting Redis keyspace notification makes the server drop the client from its
registry and close every connection it currently holds, so active sessions end
immediately.

### Generate a QR code

```bash
tiredvpn admin qr \
  -server vpn.example.com:443 \
  -secret <secret>
```

| Flag | Default | Description |
|------|---------|-------------|
| `-server` | | **required** Server address |
| `-secret` | | **required** Client secret |
| `-quic` | `true` | `quic` parameter |
| `-quic-port` | `8443` | `quicPort` parameter |
| `-strategy` | `auto` | `strategy` parameter |
| `-cover` | `api.googleapis.com` | `cover` parameter |

This command talks to no server: it formats a connection string from the
arguments and renders it. It takes no `-api` or `-api-token`.

### Connection string format

Both `admin add` and `admin qr` build the same URL:

```
tired://<server-address>?secret=<secret>
                        &strategy=<strategy>
                        &quic=<true|false>
                        &quicPort=<port>
                        &cover=<host>
                        &rtt=false
                        &rttProfile=moscow-yandex
                        &fallback=true
```

`rtt`, `rttProfile` and `fallback` are hardcoded; no flag changes them.

## REST API

The API is served on `-api-addr`, default `127.0.0.1:8080`. Request and
response read/write timeouts are 10 s.

### Authentication

When the server runs with `-api-token` (or `TIREDVPN_API_TOKEN`), **every**
endpoint - including `/health` and `/metrics` - requires:

```
Authorization: Bearer <token>
```

The comparison is constant-time. A missing, malformed or wrong header returns:

```
401 Unauthorized
{"error":"Unauthorized","code":401}
```

With no token configured, the middleware is a pass-through.

### Error format

Handler-level errors are JSON: `{"error": "<message>", "code": <status>}`.
Three routing-level errors are plain text instead, produced by `http.Error`:
`Method not allowed` (405), `Client ID required` (400) and
`Invalid client ID format` (400).

### `GET /clients`

Lists clients. `200`.

```json
{
  "clients": [
    {
      "id": "7f4e3a21-b8c2-4d19-a5f1-0e8c3d7b1920",
      "name": "alice",
      "tun_ip": "10.8.0.2",
      "max_conns": 0,
      "enabled": true,
      "active_conns": 1,
      "created_at": "2026-08-26T10:00:00Z",
      "expires_at": "2026-09-25T10:00:00Z"
    }
  ],
  "total": 1
}
```

`tun_ip` and `expires_at` are omitted when empty/zero. The secret is never
included.

### `POST /clients`

Creates a client. `201 Created`.

```
POST /clients
Content-Type: application/json

{
  "name": "alice",
  "tun_ip": "10.8.0.5",
  "max_conns": 10,
  "expires_in": "720h"
}
```

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `name` | string | yes | Empty gives `400 Name is required` |
| `tun_ip` | string | no | Fixed tunnel IP. Stored as given; not validated against `-ip-pool` |
| `max_conns` | int | no | `0` = unlimited |
| `expires_in` | string | no | Go duration. Unparsable gives `400 Invalid expires_in format (use Go duration like '720h')`. A non-positive value leaves `expires_at` zero, i.e. never |

Response:

```json
{
  "id": "7f4e3a21-b8c2-4d19-a5f1-0e8c3d7b1920",
  "name": "alice",
  "secret": "a3f1c9e2...",
  "tun_ip": "10.8.0.5",
  "max_conns": 10,
  "enabled": true,
  "created_at": "2026-08-26T10:00:00Z",
  "expires_at": "2026-09-25T10:00:00Z"
}
```

This is the only time the secret is returned. It is a 64-character hex string
generated server-side from `crypto/rand`; the request cannot supply one. New
clients are always created enabled.

Errors: `400 Invalid JSON`, `400 Name is required`, `400 Invalid expires_in
format ...`, `500 Failed to create client`.

### `GET /clients/{id}`

Client detail with runtime counters. `200`.

```json
{
  "id": "7f4e3a21-b8c2-4d19-a5f1-0e8c3d7b1920",
  "name": "alice",
  "tun_ip": "10.8.0.2",
  "max_conns": 0,
  "max_bandwidth": 0,
  "enabled": true,
  "created_at": "2026-08-26T10:00:00Z",
  "stats": {
    "client_id": "7f4e3a21-b8c2-4d19-a5f1-0e8c3d7b1920",
    "active_conns": 1,
    "total_conns": 12,
    "bytes_up": 148213,
    "bytes_down": 2910442,
    "last_seen": "2026-08-26T12:31:04Z"
  }
}
```

`{id}` must parse as a UUID, otherwise `400 Invalid client ID format`
(plain text). Unknown or non-visible ID: `404 {"error":"Client not found"}`.

`last_seen` is the time the response was generated, not the time of the
client's last activity.

### `DELETE /clients/{id}`

Deletes a client. `200`.

```json
{"deleted": true, "id": "7f4e3a21-...", "name": "alice"}
```

Errors: `400 Invalid client ID format`, `404 Client not found`,
`500 Failed to delete client`.

### `GET /stats`

Aggregate counters across visible clients. `200`.

```json
{
  "total_clients": 2,
  "total_connections": 3,
  "client_stats": [
    {
      "client_id": "7f4e3a21-...",
      "active_conns": 1,
      "total_conns": 12,
      "bytes_up": 148213,
      "bytes_down": 2910442,
      "last_seen": "2026-08-26T12:31:04Z"
    }
  ]
}
```

### `GET /health`

`200` when Redis answers a `PING` within 2 s:

```json
{"status": "healthy", "clients": 3}
```

`503` otherwise: `{"error":"Redis unhealthy: <detail>","code":503}`.

### `GET /metrics`

Prometheus text format, `Content-Type: text/plain; version=0.0.4;
charset=utf-8`. Metric names are listed in [monitoring.md](monitoring.md).

### There is no update endpoint

`/clients/{id}` handles `GET` and `DELETE` only; `/clients` handles `GET` and
`POST`. `PUT` and `PATCH` return `405 Method not allowed`. Nothing in the API
changes an existing client's `name`, `tun_ip`, `max_conns`, `max_bandwidth`,
`enabled` flag or expiry.

To disable a client, delete it (the sessions drop immediately) and create a new
one, or write the JSON record in Redis directly - the server picks the change up
through keyspace notifications, and within 30 s through version polling in any
case.

### Visibility

The read endpoints (`GET /clients`, `GET /clients/{id}`, `GET /stats`) are
served from the in-memory registry, which holds only clients that are
**enabled and not expired**. A disabled or expired client is invisible: it does
not appear in the list, `GET` by ID returns `404`, and `DELETE` returns `404`
too - its Redis record has to be removed by hand.

## Securing the API

The default bind is `127.0.0.1`, unreachable from the network. Anyone who can
reach the API without a token can create clients, delete them and read the
secret of any client they create. Set `-api-token` and keep the bind local; for
remote administration use an SSH tunnel or an authenticating reverse proxy.

```bash
# Reach a remote API over SSH
ssh -L 8080:127.0.0.1:8080 user@your-server.com

# Then, locally:
tiredvpn admin list -api http://127.0.0.1:8080 -api-token <token>
```

`TIREDVPN_API_TOKEN` works for both sides, so the token need not appear in
either command line.

## Client data model

Stored as JSON at `<redis-prefix>clients:<uuid>`.

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | UUID, server-generated |
| `name` | string | Display label |
| `secret` | string | 64-character hex, server-generated. Indexed separately at `<prefix>secrets:<sha256-prefix>` for O(1) auth lookups |
| `tun_ip` | string | Fixed tunnel IP; empty means the pool assigns one |
| `max_conns` | int | Max simultaneous connections, `0` = unlimited. Enforced on connect |
| `max_bandwidth` | int64 | Bytes/sec, `0` = unlimited. Persisted and reported by `GET /clients/{id}`, but no API sets it and no code path enforces it |
| `enabled` | bool | `false` makes the client invisible to the registry and unable to authenticate |
| `created_at` | time | Creation timestamp |
| `expires_at` | time | Zero = never |
